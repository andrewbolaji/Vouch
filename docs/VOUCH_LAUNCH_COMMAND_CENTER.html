What Add a Place can honestly promise at launch

The app can accept one restaurant, correction, city, or general suggestion per signed-in user per UTC day. That is a maximum, not a daily assignment. Suggestions enter a pending review queue. They do not automatically become voteable and never receive rank from being nominated.

Launch-safe promise: Nominate a missing restaurant. Vouch reviews it. If approved later, it may become eligible for local vouches. Only local vouches determine rank.
Do not promise yet: instant restaurant creation, public photo upload, automatic city activation, a visible submission status tracker, or guaranteed entry into the Top 10.

RevenueCat, in the safe order.

The dashboard work and the code work meet in the middle. Do not archive a paid build until the exact Apple product IDs are in the app and a sandbox purchase has completed end to end.

Stop before enabling HMAC signing.

RevenueCat currently documents the header as X-RevenueCat-Webhook-Signature, formatted as t=timestamp,v1=signature, with the HMAC computed over timestamp.raw_body. The current Vouch code expects a different header and hashes only the raw body. Codex must fix and test that code before you enable signing in RevenueCat or flip SIGNATURE_ENABLED.
